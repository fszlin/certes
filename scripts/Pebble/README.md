# Local ACME integration tests

Run from the repository root with a .NET 10 SDK and Docker with Compose:

```sh
docker compose -f scripts/Pebble/compose.yml up -d
bash scripts/Pebble/wait.sh
dotnet test test/Certes.Tests.Integration/Certes.Tests.Integration.csproj -f net10.0 -p:SkipSigning=true
docker compose -f scripts/Pebble/compose.yml down
```

Docker Desktop on macOS ARM64 is verified locally. GitHub Actions uses Docker on
Linux x64. Podman with a running machine and Compose provider may work with the
same file, but has not been verified. Unit tests do not need containers.

## Topology and trust

- Pebble ACME: `https://localhost:14000/dir`
- Pebble management/issuance root: `https://localhost:15000/roots/0`
- Challenge responder management: `http://localhost:8055`
- Container network: `10.30.50.0/24`; Pebble resolves test names through
  challtestsrv at `10.30.50.3:8053`. HTTP/TLS validation stays inside that network
  on ports 5002/5001. No public DNS, Azure account, or domain ownership is needed.

Host ports bind only to IPv4 loopback. If the ports/subnet conflict with another
local service, stop that service or adjust both the Compose and helper settings.
The test helper uses fixed local endpoints, disables proxies and redirects, and
has no public-CA fallback.

Images are Pebble **2.10.1**, pinned to multi-platform manifest digests. Real
challenge validation is enabled. Random nonce rejection, authorization reuse,
and artificial validation sleeps are disabled for repeatable baseline runs.
Missing-response tests for each challenge type ensure validation is not bypassed.

`localhost.pem` is the public server certificate from
[Pebble v2.10.1](https://github.com/letsencrypt/pebble/blob/v2.10.1/test/certs/localhost/cert.pem)
(upstream BSD-3-Clause license). The .NET 10 test client pins its exact DER bytes,
checks validity and hostname, and restricts the exception to localhost ports
14000/15000. No global TLS callback or trust-store modification is used. Do not
install Pebble certificates in system trust stores or use its keys in production.
The server certificate expires October 3, 2027; update the pinned image and
certificate together before then. It is distinct from the ephemeral issuance
root, which is fetched at startup and supplied to the existing export APIs.

## Scope and troubleshooting

The 13 integration cases cover account discovery/update/deactivation/key change,
HTTP-01, DNS-01, TLS-ALPN-01, wildcard issuance, RSA/ECDSA leaf keys, certificate
download, PEM/PFX export, revocation, and failed validation. They do not prove
public-CA interoperability or production polling correctness. Test-only helpers
bound polling to 60 seconds with a 10-second HTTP request timeout; the README
`Generate` example explicitly requests up to 60 retries. Production retry behavior
is unchanged. TLS-ALPN responses are generated by challtestsrv from Certes key
authorization, so this flow does not test Certes's `TlsAlpnCertificate` generator.

The local harness runs on `net10.0`; its retained `net462` target is compile-only
and deliberately refuses network initialization rather than installing a global
TLS bypass. Images must be pulled and NuGet packages restored before offline use.

Pebble loses all accounts, orders, and issuer keys when its container restarts.
Run only one test process against a stack at a time. Each process initializes
known test accounts once and clears challenge responses after validation; test
classes can run in parallel using distinct names/tokens. To reset everything:

```sh
docker compose -f scripts/Pebble/compose.yml down
docker compose -f scripts/Pebble/compose.yml up -d
bash scripts/Pebble/wait.sh
```

If setup fails, inspect `docker compose -f scripts/Pebble/compose.yml logs`.
Failures are errors, not skipped tests. CI always tears the stack down, and prints
container logs on failure. The legacy Functions helper is retained for a separate
retirement change; integration tests no longer call it.
